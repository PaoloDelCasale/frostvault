### BUG-001: process_job recover branch lacks status whitelist

- **Source:** Code Review Pass 1 + Pass 2
- **Severity:** Medium (Phase 5 challenge DOWNGRADED from High)
- Primary requirement: REQ-002
- Covers: [REQ-002/cell-RECOVER-PROCESS_JOB]
- **File:** `app/storage.py:2223-2224`
- **Disposition:** code-fix
- **Disposition rationale:** The dispatcher intentionally whitelists statuses for every peer action; recover is the only mutation path without a conjunct. Selection filtering in `process_jobs_once` is not a substitute for dispatcher defense-in-depth — especially under stale job dicts when DB status has left `{queued, retrying, restoring}`. Challenge Round 2 confirmed the stale-dict / RestoreObject composition defect while reducing severity because today's poller largely masks it.
- **Divergence description:** Documented/peer intent is that each `process_job` action runs only for an explicit status set. Recover executes for any non-cancelled status that reaches the branch.
- **Documented intent:** REQ-002 — recover only for `{queued, retrying, restoring}`; pending_approval must no-op.
- **Code behavior:** `elif job["action"] == "recover": process_recover(job)` with no status check (`app/storage.py:2223-2224`).
- **Expected:** `elif job["action"] == "recover" and job["status"] in {"queued", "retrying", "restoring"}:`
- **Actual:** Status-ungated recover dispatch.
- **Minimal reproduction:** Construct a job dict `action=recover`, `status=pending_approval` (or call `process_job` after DB status is `pending_approval` while dict still says `queued`); observe `process_recover` entry / RestoreObject path instead of False no-op.
- **Spec basis:** Code inconsistency with peer dispatcher guards; inferred REQ-002 from `process_job` whitelist pattern (Tier 5). Mechanical extract: `quality/workspace/mechanical/process_job_action_branches.txt`.
- **fix_type:** code
- **Proposed fix:** Add status conjunct aligned with selection + restoring poll; return False otherwise.
- **Regression test:** `quality/test_regression.py::TestBug001::test_bug_001_recover_requires_status_whitelist`
- **Patches:** `quality/workspace/patches/BUG-001-regression-test.patch`, `quality/workspace/patches/BUG-001-fix.patch`
- **Writeup:** `quality/workspace/writeups/BUG-001.md`
- **Challenge:** `quality/challenge/BUG-001-challenge.md` — **Verdict:** DOWNGRADED

### BUG-002: Reversible cloud hide does not detect concurrent newer Archive Version

- **Source:** Code Review Pass 1 + Pass 2 + Pass 3
- **Severity:** Medium (Phase 5 challenge DOWNGRADED from High)
- Primary requirement: REQ-004
- Covers: [REQ-004/cell-DETECT_CURRENT_MISMATCH-CLOUD_ARCHIVE, REQ-004/cell-DETECT_CURRENT_MISMATCH-RENAME_HIDE]
- Consolidation rationale: Both `process_cloud_archive` and `process_rename` hide-old-key issue unversioned `delete_object` without comparing the live current generation to the intended target; a shared Head/compare-or-abort helper before delete closes both cells.
- **File:** `app/storage.py:2099-2102` (primary); rename `app/storage.py:1622-1625`
- **Disposition:** code-fix
- **Disposition rationale:** Creating a delete marker requires an unversioned delete in S3, but REQ-004 still requires detecting when current ≠ scheduled generation. The code loads `provider_version_id` for the scheduled Archive Version and then never uses it for comparison — a concrete omission. Challenge confirmed integrity failure on mismatch while lowering severity because the one-active-file job gate reduces in-app race likelihood.
- **Divergence description:** Schedule pins `archive_version_id`; execute hides whatever is current without mismatch detection/audit.
- **Documented intent:** REQ-004 conditions — abort or audit when current key generation ≠ scheduled expectation.
- **Code behavior:** `s3_client().delete_object(Bucket=..., Key=object_key)` with no `VersionId` and no prior Head compare (`2099-2102`).
- **Expected:** Head current version (or equivalent); if ≠ scheduled `provider_version_id`, fail Job / audit actual target before marker.
- **Actual:** Silent marker on whatever is current, including a newer concurrent upload.
- **Minimal reproduction:** Schedule cloud-archive against V1; upload V2 to same key before worker runs; observe delete marker hiding V2 while Job completes narrating archival of scheduled context.
- **Spec basis:** Code inconsistency with VersionId pinning elsewhere (REQ-001/REQ-013); inferred REQ-004 Tier 5; README recovery/cleanup VersionId language.
- **fix_type:** code
- **Proposed fix:** Before unversioned delete, `head_object` current key; compare `VersionId` to scheduled `provider_version_id`; abort/audit on mismatch. Apply same helper to rename hide.
- **Regression test:** `quality/test_regression.py::TestBug002::test_bug_002_cloud_archive_detects_concurrent_version`
- **Patches:** `quality/workspace/patches/BUG-002-regression-test.patch`, `quality/workspace/patches/BUG-002-fix.patch`
- **Writeup:** `quality/workspace/writeups/BUG-002.md`
- **Challenge:** `quality/challenge/BUG-002-challenge.md` — **Verdict:** DOWNGRADED

### BUG-004: csrf_token_for ignores session_version force-logout

- **Source:** Code Review Pass 1 + Pass 2
- **Severity:** Low (Phase 5 challenge DOWNGRADED from Medium)
- Primary requirement: REQ-008
- **File:** `app/sessions.py:115-137` vs `app/sessions.py:95-96`
- **Disposition:** code-fix
- **Disposition rationale:** Force-logout bumps `users.session_version`; `resolve_session` rejects skew but CSRF middleware uses `csrf_token_for`, which still returns the token. Not an end-to-end auth bypass today (endpoints use `current_user`), but `session_version` is the same liveness axis as `revoked_at`/expiry that this helper already applies. Challenge confirmed parity gap; severity Low for defense-in-depth hygiene.
- **Divergence description:** Session revocation via session_version is incomplete at the CSRF layer.
- **Documented intent:** REQ-008 — CSRF lookup should return None when versions diverge, matching `resolve_session`.
- **Code behavior:** `csrf_token_for` SELECT omits session_version join/compare; returns token for non-revoked non-expired rows.
- **Expected:** None when `sessions.session_version != users.session_version`.
- **Actual:** CSRF token still returned; middleware at `main.py:289-300` can accept it.
- **Minimal reproduction:** Create session; bump user `session_version`; `resolve_session` → None; `csrf_token_for` → non-None token.
- **Spec basis:** ADR 0005 host/CSRF/reauth hardening intent; code peer `resolve_session`; REQ-008 Tier 5.
- **fix_type:** code
- **Proposed fix:** Join users and compare session_version inside `csrf_token_for` (read-only; still no last_seen touch).
- **Regression test:** `quality/test_regression.py::TestBug004::test_bug_004_csrf_honors_session_version`
- **Patches:** `quality/workspace/patches/BUG-004-regression-test.patch`, `quality/workspace/patches/BUG-004-fix.patch`
- **Writeup:** `quality/workspace/writeups/BUG-004.md`

### BUG-006: Startup cleanup destroys free-space claim files before reconcile

- **Source:** Spec Audit (Auditor 2 minority + executable probe) — triage CONFIRMED
- **Severity:** High (Phase 5 challenge CONFIRMED)
- Primary requirement: REQ-009
- **File:** `app/storage.py:353-357`, `app/storage.py:1028`, `app/main.py:160-161`, `app/storage.py:1092-1109`
- **Disposition:** code-fix
- **Disposition rationale:** REQ-009 requires claim restore / salvageable path after free-space verification failure. Startup deletes `.cleanup-*.tmp` claims via `is_restore_temporary_name` before reconcile, then marks missing Local Copies as successfully freed — data loss across restart. Challenge both rounds agreed High severity.
- **Divergence description:** Free-space salvage claims are treated as disposable restore residues at process start.
- **Documented intent:** Failed or interrupted claim must restore Local Copy or preserve salvage path.
- **Code behavior:** Cleanup unlinks cleanup claims; reconcile missing-path → `status='completed'` without `restore_claimed_local_copy`.
- **Expected:** Exclude cleanup claims from abandoned-restore cleanup; reconcile must attempt claim restore before completing.
- **Actual:** Claim deleted; Job completed as freed.
- **Minimal reproduction:** Crash after `local_path.rename(claimed_path)` mid free-space; restart; observe claim gone and Job completed.
- **Spec basis:** REQ-009 Tier 3; UC-08; contracts on claim restore.
- **fix_type:** code
- **Proposed fix:** Narrow `cleanup_abandoned_restore_files` to restore/verify temps only; teach reconcile to restore `.cleanup-*.tmp` siblings.
- **Regression test:** `quality/test_regression.py::TestBug006::test_bug_006_startup_preserves_free_space_claims`
- **Patches:** `quality/workspace/patches/BUG-006-regression-test.patch`, `quality/workspace/patches/BUG-006-fix.patch`

### BUG-007: Operating windows compared as lexicographic strings

- **Source:** Spec Audit (Auditor 1 minority + executable probe) — triage CONFIRMED
- **Severity:** Medium (Phase 5 challenge CONFIRMED)
- Primary requirement: REQ-012
- **File:** `app/services/operation_policies.py:96-97`
- **Disposition:** code-fix
- **Disposition rationale:** After int-parsing HH:MM for shape, comparison uses raw strings. `OperatingWindowModel` allows length 4–5, so non-padded inputs are HTTP-legal. Probe accepts `10:00`–`9:30` and rejects `9:30`–`10:00`. Challenge both rounds confirmed.
- **Divergence description:** REQ-012 time ordering is not enforced for non-padded stamps.
- **Documented intent:** `start > end` → ValueError; valid `start < end` accepted.
- **Code behavior:** `if start >= end:` string compare.
- **Expected:** Compare parsed `(hour, minute)` tuples (matching `_parse_hhmm` semantics).
- **Actual:** Lexicographic compare; inverted non-padded windows accepted.
- **Minimal reproduction:** `_normalize_windows([{"weekday":1,"start":"10:00","end":"9:30"}])` succeeds.
- **Spec basis:** REQ-012 Tier 3; QUALITY Scenario 9 adjacent.
- **fix_type:** code
- **Proposed fix:** Retain parsed hour/minute and compare tuples.
- **Regression test:** `quality/test_regression.py::TestBug007::test_bug_007_windows_compare_as_times_not_strings`
- **Patches:** `quality/workspace/patches/BUG-007-regression-test.patch`, `quality/workspace/patches/BUG-007-fix.patch`
- **Writeup:** `quality/workspace/writeups/BUG-007.md`
- **Challenge:** `quality/challenge/BUG-007-challenge.md` — **Verdict:** CONFIRMED
