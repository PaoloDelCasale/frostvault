## Domain questions (answered inline with findings)

- **API surface inconsistencies:** `/api/recover/estimate` prices via active
  `cost_price_books`; worker high-impact hold uses hardcoded
  `DEFAULT_RESTORE_PRICING_EUR_PER_GIB` — same Glacier action, two rate books.
- **Ad-hoc structured parsing:** restore header parsing and object_key↔path
  conversion exist, but crypt recover never routes VersionId downloads through
  `object_key_to_path`.
- **Inputs a domain expert tries:** recover while an unscanned file sits on disk;
  recover an Archive Version created before a rename on a crypt vault; reactivate
  a deactivated user and reuse the old cookie; change price book then rely on
  estimate-driven approval.
- **Silently wrong metadata/config:** admin-edited restore rates never reach
  `process_recover` approval math.

## Findings

### U3-1: Recover atomic-replace overwrites on-disk files when catalog says absent

- **Trace:** `ArchiveCatalog.get_job_target` exposes `local_presence`
  (`app/catalog.py:234-264`) → `process_recover` rejects only
  `local_presence == "present"` (`app/storage.py:1899-1900`) → download to
  temp → `temporary.replace(destination)` (`app/storage.py:2024-2046`) with
  **no** `os.path.lexists(destination)` / exclusive-create gate.
- **Hypothesis:** After free-space, a user or external process can recreate a
  file at the Vault File path before the next scan. Catalog still says
  `missing`/`absent`. Recover succeeds and silently destroys that on-disk
  content via `Path.replace`.
- **Domain wrongness:** Product language treats Local Copy as the observed
  filesystem representation; overwriting an existing regular file without a
  conflict check is silent data loss, not “restore missing Local Copy”.
- **Severity:** Critical / High
- **Dedup:** Not BUG-001 (dispatcher whitelist). Not BUG-006 (startup claim
  cleanup). Distinct TOCTOU catalog-vs-disk class.
- **Candidate:** CAND-U3-001 → promote **BUG-012**

### U3-2: Crypt/encrypted recover ignores Archive Version `object_key` and uses current job path

- **Trace:** `process_recover` loads `object_key` + `provider_version_id`
  (`app/storage.py:1902-1905`, via `get_job_target`) →
  `download_exact_version_plaintext(..., object_key=..., ...)`
  (`app/storage.py:2032-2037`) → crypt/name-encrypt branch builds rclone
  source from `job['path']` only (`app/storage.py:1829-1852`) while the
  plaintext boto3 branch correctly uses `Key=object_key`
  (`app/storage.py:1858-1861`). Helper `object_key_to_path` exists
  (`app/storage.py:281-309`) but is unused on this path.
- **Hypothesis:** After a confirmed rename, historical Archive Versions retain
  the pre-rename `object_key` / encrypted name. Recovering that VersionId via
  rclone at the **current** logical path addresses a different S3 key than the
  VersionId belongs to → wrong object, empty download, or digest failure that
  masks the real identity bug. Plaintext path is correct; crypt path is not
  parity-safe (violates REQ-001 crypt surface intent).
- **Severity:** High
- **Dedup:** Not BUG-002 (hide VersionId). Not BUG-008 (scan identity fork).
  Not CAND-006 (rclone VersionId flag propagation — different layer).
- **Candidate:** CAND-U3-002 → promote **BUG-013**

### U3-3: Reactivating a User does not bump `session_version` — old Sessions revive

- **Trace:** `update_user` applies `active=%s` without
  `session_version=session_version+1` (`app/main.py:2682-2691`); only password
  changes bump the version. `resolve_session` denies inactive users but accepts
  the same session once `active` is true again if versions still match
  (`app/sessions.py:86-96`). Force-logout elsewhere relies on version bumps
  (REQ-008 family).
- **Hypothesis:** Admin deactivates a compromised account (sessions become
  inert because `active=FALSE`). Later reactivation for legitimate return
  **re-enables every unexpired, unrevoked Session cookie** minted before
  deactivation — including attacker-held cookies — without requiring a fresh
  login.
- **Severity:** High
- **Dedup:** Adjacent to BUG-004 (CSRF vs session_version) but distinct:
  BUG-004 is CSRF lookup omitting version; this is missing version bump on
  active-state transitions.
- **Candidate:** CAND-U3-003 → promote **BUG-014**

### U3-4: Restore high-impact gating uses different rate books than the estimate API

- **Trace:** `POST /api/recover/estimate` loads `get_active_price_book` and
  `estimate_restore_cost` (`app/main.py:2181-2197`). Queue path and
  `process_recover` call `estimate_restore` with module defaults
  (`app/main.py:2087-2092`, `app/storage.py:1925-1936`;
  `app/services/restore_estimates.py:49-60`). `builtin_price_book` seeds from
  the same defaults (`app/services/cost_estimates.py:97-108`), but any
  activated admin `cost_price_books` row diverges.
- **Hypothesis:** Operator sees `high_impact=true` (or false) from estimate
  based on configured rates; worker later holds or proceeds using hardcoded
  rates. Silent approval-bypass or false holds for irreversible RestoreObject.
- **Severity:** High
- **Dedup:** Net-new. Not BUG-007 (window strings). Not former BUG-003.
- **Candidate:** CAND-U3-004 → promote **BUG-015**

### U3-5: Restart recover reconciliation deletes destination files (reviewed)

- **Trace:** `reconcile_interrupted_jobs` for recover in
  `downloading`/`verifying` unlinks `target` if it is a regular file
  (`app/storage.py:1059-1071`). Unit test
  `test_restart_reconciles_completed_and_incomplete_recoveries` **expects**
  this (`tests/test_storage_cleanup.py:653-707`).
- **Hypothesis residual:** A user-written file that appears at the path while
  a recover Job is interrupted could be deleted. Product currently treats any
  destination file during interrupted recover as non-durable worker output.
- **Severity:** Medium residual
- **Dedup / disposition:** DEMOTED — intentional + tested contract; residual
  risk tracked as DC-004.
- **Candidate:** demote DC-004

### U3-6: Metadata backup download lacks step-up reauth

- **Trace:** `POST .../metadata-backups/run` requires `require_recent_reauth`
  (`app/main.py:1788-1792`); `GET .../download/{run_id}` is admin-only
  (`app/main.py:1828-1832`). ADR-0005 scopes reauth to **mutations** and named
  sensitive actions; docs say “reauthentication required for runs”.
- **Disposition:** DEMOTED DC-005 — GET download is outside ADR mutation scope;
  docs bind reauth to runs. Re-promote if a Tier-1/2 doc mandates reauth on
  ciphertext download.
- **Candidate:** demote DC-005
