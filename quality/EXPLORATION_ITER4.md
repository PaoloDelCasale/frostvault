## Findings

### P4-1: Metadata verify promotes a different DB run than the artifact checked

- **Invariant:** A `metadata_backup_runs` row may be marked `verified` only after
  restore-verifying **that row’s** artifact (path/digest), matching download
  resolution which already binds run → digest/path
  (`app/services/metadata_backups.py:747-780`).
- **Left (backup create):** `run_metadata_backup` persists `digest_sha256`,
  `local_path`, `filename` on the run row
  (`app/services/metadata_backups.py:677-693`).
- **Right (scheduled verify):** `_verify_latest_metadata_backup_once` verifies
  `list_local_backup_files(...)[0]` (newest filename) then
  `UPDATE ... SET status='verified' ... WHERE id=<newest status=succeeded id>`
  with **no** digest/path join (`app/storage.py:2563-2601`).
- **Diff:** Download path enforces digest/path binding; verify path does not.
  Orphan newer `.bak.enc`, restored DB with reordered ids, or a failed run’s
  leftover file can verify artifact A while stamping run B.
- **Classification:** **Net-new → BUG-016** (High). Distinct from rejected
  former BUG-003 (list-only `ok:True` without restore) and DC-011
  (pg_restore warning counts).
- **Candidate:** CAND-P4-001

### P4-2: Cloud-archive observability is fail-closed after non-idempotent S3 hide

- **Invariant:** After an external storage mutation that cannot be rolled back,
  observability failures must not fail the job and re-queue another mutation
  (parity with local automatic cleanup, which treats audit/notify as
  best-effort — `record_automatic_cleanup_outcome` `app/storage.py:1654-1697`).
- **Left (local cleanup):** durable free-space work completes; audit/notify
  exceptions are swallowed into `worker_error_store`
  (`app/storage.py:1654-1697`).
- **Right (cloud archive):** `delete_object` issues a Delete Marker
  (`app/storage.py:2099-2105`), then a single DB block records the marker and
  calls `record_archive_completed` which audits **and** notifies without a
  best-effort guard (`app/storage.py:2107-2125`,
  `app/services/cloud_deletion.py:897-928`). Any exception before
  `set_job(... completed ...)` falls through `process_job` failure handling
  (`app/storage.py:2259+`) → job `failed` / retryable → another
  `delete_object` → additional Delete Marker.
- **Diff:** Same class of post-mutation observability; opposite failure policy.
  S3 mutation is outside the DB transaction (cannot roll back).
- **Classification:** **Net-new → BUG-017** (High). Not BUG-002 (concurrent
  VersionId detection). Not BUG-009 (rename audit connection). Not DC-008
  (notification delivery unwired — here enqueue itself can abort the job).
- **Candidate:** CAND-P4-002

### P4-3: Cancel recover clears `restore_state` after non-cancellable RestoreObject

- **Invariant:** Once AWS accepts `RestoreObject`, FrostVault cannot cancel the
  Glacier work and must retain `restore_state` / `restore_expiry` so a later
  recover can resume polling. Worker already documents this:
  `"RestoreObject cannot be cancelled after AWS accepts it"`
  (`app/storage.py:2016-2021`).
- **Left (worker accept):** after `restore_object`, persists
  `restore_state='restoring'` via `update_restore_state`
  (`app/storage.py:1995-2015`).
- **Right (user cancel):** cancel path always calls
  `clear_restore_state_for_jobs` for recover actions
  (`app/main.py:2323-2327`, `app/catalog.py:287-303`), wiping
  `restore_state` and `restore_expiry`.
- **Diff:** Cancel erases the only durable pointer to an in-flight AWS restore
  the product admits it cannot stop. Subsequent recover may re-issue
  RestoreObject and loses expiry tracking.
- **Classification:** **Net-new → BUG-018** (High). Not DC-004 (restart unlink
  of destination file). Not BUG-001 (dispatcher whitelist).
- **Candidate:** CAND-P4-003

### P4-4: OIDC self-link lacks `require_recent_reauth` vs admin invite

- **Invariant (candidate):** Binding a new durable login method should require
  fresh proof, matching admin invite creation (`app/main.py:2643-2648`).
- **Left:** `POST /api/admin/invites` → `admin_user` + `require_recent_reauth`.
- **Right:** `GET /auth/oidc/link` → `current_user` only; creates invite + OIDC
  begin (`app/main.py:1079-1096`).
- **Classification:** **Demote DC-013** — adjacent to DC-007 (GET side-effect /
  CSRF). Admin vs self threat models may differ intentionally; needs ADR-level
  step-up requirement for self-link, not only invite admin path.
- **Candidate:** demote DC-013

### P4-5: Price-book config accepts keys/rates execution cannot safely consume

- **Left:** `CostPriceBookCreate` accepts raw `dict[str, float]` with no
  normalization (`app/main.py:730-739`).
- **Right:** `estimate_restore` uppercases storage class and exact-matches
  tiers (`app/services/cost_estimates.py:222-269`).
- **Classification:** **Demote DC-014** — refinement/adjacent to BUG-015
  (estimate vs worker book skew). Config-time validation is a separate hygiene
  risk; not promoted without showing a distinct production failure mode beyond
  BUG-015’s worker hardcoding.
- **Candidate:** demote DC-014

### P4-6: Cloud-archive failure path lacks dedicated audit event

- **Left:** purge partial failures audit (`cloud_deletion.py` failure helpers).
- **Right:** `process_cloud_archive` exceptions → generic `set_job(failed)` only.
- **Classification:** **Demote DC-015** — observability hygiene; primary
  severity captured by BUG-017’s non-idempotent retry. Re-promote if a contract
  requires `cloud_deletion.archive_failed` specifically.
- **Candidate:** demote DC-015
