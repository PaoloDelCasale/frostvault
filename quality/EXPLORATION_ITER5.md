- **Original claim:** `pg_restore --list` success → `ok: True` → run `verified`.

  tagged `verification_mode: "pg_restore_list"`; REQ-005 Tier-5 aspiration).

  producer `ok`; docs do not forbid degraded TOC verify.
- **Falsification attempt:** Re-read `docs/metadata-backups.md:41-44` (“restores
  into an isolated temporary database”). That sentence describes the *primary*
  path, not a prohibition of the tagged fallback. Challenge gate artifacts under
  `quality/challenge/BUG-003-challenge.md` and
  `quality/challenge/dismissed/former-003-*` remain consistent.
- **Probe:** Confirm list-only branch still returns `verification_mode=
  "pg_restore_list"` and is distinct from temp_database (see A-DC-011).
- **Verdict:** **PRESERVED-REJECTED** — no new contract invalidating Round 2.

### A-4: DC-002 — PostgreSQL invite double-redeem

- **Dismissal:** Needs concurrent Postgres stress.
- **Fresh evidence:** `redeem_invite` SELECT → INSERT identity → UPDATE without
  `WHERE redeemed_at IS NULL` / row lock (`invites.py:84-107`). Schema UNIQUE is
  only `(issuer, subject)` — not single-redeem on invite id. ADR-0003:
  “single-use, expiring Invite”. Two subjects can both observe `redeemed_at IS
  NULL`, both bind, both UPDATE — second clobbers redeemer fields.
- **Probe (structural):** Assert UPDATE includes conditional redeem guard;
  optional PG stress when `TEST_POSTGRES_URL` set.
- **Verdict:** **PROMOTED → BUG-022** (Medium). Former id **DC-002** preserved.

### A-11: DC-011 — temp_database verify `ok: True` without proven tables

- **Dismissal:** Adjacent to former BUG-003; don’t reopen without distinct
  evidence.
- **Fresh evidence (distinct):** When `createdb` **succeeds**, path uses
  `verification_mode: "temp_database"`. `pg_restore` rc∈{0,1} accepted; if
  subsequent `psql` COUNT fails (tables missing), counts stay `None` and
  function still returns `"ok": True` (`metadata_backups.py:458-500`). Consumer
  stamps `verified` on `ok` alone (`storage.py:2578-2600`). Docs claim
  verification “restores into an isolated temporary database”
  (`docs/metadata-backups.md:41-44`). This is **not** the intentional
  list-only fallback.
- **Probe:** Mock subprocess: list=0, createdb=0, restore=1, psql=1 → assert
  not ok / BackupError.
- **Verdict:** **PROMOTED → BUG-019** (High). Former id **DC-011** preserved.
  former BUG-003 remains REJECTED.

### A-12: DC-013 — self-link without `require_recent_reauth`

- **Dismissal:** May be intentional without ADR mandating step-up for self-link.
- **Fresh evidence:** ADR-0005: “Sensitive actions — every `/api/admin/*`
  mutation, **invite creation**, and freeing local space — require a
  `reauth_at`…”. Admin invite: `Depends(require_recent_reauth)`
  (`main.py:2643-2648`). Self-link `GET /auth/oidc/link` creates invite via
  `create_invite` with **only** `current_user` (`main.py:1079-1096`). ADR-0003
  states self-link *is* invite issuance turned inward. Adjacent: callback
  `mark_reauthenticated` without requiring `prompt=login` on self-link
  (`main.py:1131-1135` vs reauth `984-988`) — stale session can mint invite and
  refresh reauth window via IdP SSO cookie.
- **Probe:** Assert `oidc_link` Depends includes `require_recent_reauth`; stale
  session may create invite today.
- **Verdict:** **PROMOTED → BUG-021** (High). Former id **DC-013** preserved.
  DC-007 stays demoted (CSRF chain unproven).
