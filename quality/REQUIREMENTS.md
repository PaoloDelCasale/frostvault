# Requirements — FrostVault

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-07-23 · Project: FrostVault

Total requirements: **30** (REQ-001..REQ-030; REQ-028..030 from parity iteration)

## Project overview

FrostVault is a self-hosted FastAPI archive that catalogs Local Copies on disk, uploads verified Archive Versions into versioned Amazon S3 (optionally through Rclone crypt remotes), frees local space only when an exact verified VersionId still exists, and recovers that exact generation back to disk. Operators and owners share a vault-scoped file-manager UI; viewers stay read-only. Authentication is OIDC for day-to-day use, with a network-gated break-glass administrator password for emergencies. Metadata may live in SQLite or PostgreSQL; the process refuses to start unless Alembic reports the expected head revision.

Primary personas: **vault owners** (sharing, policy, destructive lifecycle including free-local-space), **operators** (upload and recover), **viewers** (browse/search), and **break-glass admins** (restricted network path). Design philosophy emphasizes irreversible-action friction (reauthentication, owner-only deletes, VersionId pinning on recovery/purge), defense-in-depth between optimistic HTTP queues and worker safety gates, and dual-path correctness where crypt remotes and plaintext boto3 must preserve the same Archive Version identity.

Data flow: scan/browse → catalog identity → upload Job → S3 object + VersionId → optional free-space Job (claim/rehash/unlink) → optional recover Job (exact VersionId download + digest check) → optional cloud-archive (delete marker) / cloud-purge (versioned deletes). Cross-cutting risks concentrate in concurrent writers against the same S3 key, dispatcher status gating, proxy/IP composition for break-glass, and documentation drift around who may free local space.

Formal docs intake (`reference_docs/`) is absent this run; requirements are Tier 3 (code+in-repo docs as source of truth) or Tier 5 (inferred). Where README conflicts with `vault_roles` + HTTP + tests, code/tests win and README is a compensation target (REQ-003).

## Use cases

### UC-01 — Exact Archive Version recovery (plaintext)
- **Actor:** Worker / vault operator
- **Preconditions:** Verified available Archive Version with `provider_version_id`; plaintext vault
- **Steps:** 1) Operator queues recover. 2) Worker calls `download_exact_version_plaintext` boto3 branch. 3) Digest verified. 4) Atomic replace restores Local Copy.
- **Postconditions:** Local presence linked to the pinned VersionId; Job succeeded
- **Alternative paths:** Digest mismatch fails Job; cancel mid-download stops work
- **Requirements:** REQ-001

### UC-02 — Exact Archive Version recovery (crypt)
- **Actor:** Worker / vault operator
- **Preconditions:** Crypt vault secrets decryptable; VersionId known
- **Steps:** 1) Queue recover. 2) rclone `copyto` with `--s3-version-id`. 3) Digest verified. 4) Atomic replace.
- **Postconditions:** Same identity guarantees as UC-01
- **Alternative paths:** rclone missing file → RuntimeError; wrong generation that fails digest → Job failure
- **Requirements:** REQ-001

### UC-03 — Dispatcher refuses recover outside allowed statuses
- **Actor:** Worker
- **Preconditions:** Recover Job row exists with status outside {queued, retrying, restoring}
- **Steps:** 1) `process_job` evaluates action/status. 2) Must no-op without RestoreObject side effects.
- **Postconditions:** Status unchanged; no AWS restore cost incurred
- **Alternative paths:** restoring + young `updated_at` defers (return False)
- **Requirements:** REQ-002

### UC-04 — Operator denied free local space
- **Actor:** Operator User
- **Preconditions:** Authenticated operator; `ALLOW_LOCAL_DELETE=true`
- **Steps:** 1) POST `/api/free-space`. 2) Role check fails.
- **Postconditions:** HTTP 403; no free-space Job created
- **Alternative paths:** Owner with reauth succeeds to queue (worker still enforces fingerprint)
- **Requirements:** REQ-003, REQ-016

### UC-05 — Cloud-archive concurrent newer version
- **Actor:** Worker / S3
- **Preconditions:** Job queued against archive_version V1; V2 uploaded to same key before execute
- **Steps:** 1) Execute `process_cloud_archive`. 2) System must detect/abort/audit mismatch rather than silently hide V2 without record.
- **Postconditions:** Catalog/audit reflect actual marker target
- **Alternative paths:** No concurrent writer → marker hides intended current key; missing marker VersionId fails Job
- **Requirements:** REQ-004

### UC-06 — Metadata backup list-only must not look fully verified
- **Actor:** Backup verifier / operator
- **Preconditions:** PostgreSQL dump listable; `createdb` fails
- **Steps:** 1) `verify_restore_isolated` runs list. 2) createdb fails. 3) Outcome must not be consumed as full isolated-restore success.
- **Postconditions:** Operator alerted / non-verified status
- **Alternative paths:** Full createdb+restore path sets counts and schema revision
- **Requirements:** REQ-005

### UC-07 — Break-glass denied for forged client IP
- **Actor:** Untrusted client behind misconfigured or correctly configured proxy
- **Preconditions:** Peer not trusted OR XFF forged
- **Steps:** 1) `resolve_client_ip` selects address. 2) `is_break_glass_allowed` evaluates.
- **Postconditions:** Fail-closed deny when IP missing/unparseable/outside CIDRs (loopback always allowed)
- **Alternative paths:** Trusted proxy + legitimate XFF allows configured admin network
- **Requirements:** REQ-006, REQ-007

### UC-08 — Free-space claim restore on verification failure
- **Actor:** Worker
- **Preconditions:** Owner queued free-space; claim rename succeeded; rehash fails
- **Steps:** 1) Claim Local Copy. 2) Verification fails. 3) `restore_claimed_local_copy` restores.
- **Postconditions:** Original path restored or hard error cites claim path for salvage
- **Alternative paths:** Successful rehash → unlink claim
- **Requirements:** REQ-009

## Cross-cutting concerns

- **VersionId pinning:** Recovery and purge pin provider VersionId; reversible hide paths currently create delete markers on “current” without pinning the scheduled generation (REQ-001, REQ-004, REQ-013).
- **Authorization matrix:** Owner ⊃ operator ⊃ viewer; destructive local free-space is owner-only in code/tests despite README Users wording (REQ-003, REQ-016, REQ-017).
- **Proxy composition:** Break-glass trustworthiness equals Trusted Proxy configuration quality (REQ-006, REQ-007).
- **Queue vs worker:** HTTP may optimistically enqueue; workers enforce irreversible safety (REQ-009, REQ-018).
- **Schema gate:** Process will not run on stale DBs (REQ-010).

## Archive Version recovery

Exact recovery is the product promise: Local Copies may be deleted only because a specific S3 generation remains available. Both plaintext and crypt download surfaces must preserve that identity.

### REQ-001: Exact Archive Version recovery must pin provider VersionId on every download surface

- **Tier:** 3
- **Functional section:** Archive Version recovery
- **Pattern:** parity
- **Specificity:** specific
- **Summary:** When recovering a file, every download implementation must require and use the Archive Version's `provider_version_id`; path-only current-object downloads are forbidden.
- **User story:** As an operator recovering a file, I expect the exact Archive Version I selected to be restored **so that** a newer upload cannot silently replace the bytes I verified.
- **Implementation note:** `download_exact_version_plaintext` raises without VersionId; crypt branches pass `--s3-version-id=`; plain branch uses boto3 `VersionId`; `process_recover` rehashes.
- **Conditions of satisfaction:**
  1. Empty `provider_version_id` raises before any network download.
  2. Plain path calls `get_object(..., VersionId=provider_version_id)`.
  3. Crypt paths include `--s3-version-id={provider_version_id}` in rclone args.
  4. Digest mismatch fails the Job without promoting local presence as verified.
- **Alternative paths:** name-encrypt rclone runtime config; content-encrypt configured remote; plaintext boto3.
- **Use cases:** UC-01, UC-02
- **References:** `app/storage.py:1813-1862`, `app/storage.py:1884-2044`; README Local cleanup safety / recovery

## Job dispatcher

The worker multiplexes upload, rename, recover, free-space, cloud-archive, and cloud-purge. Status gates prevent double side effects when selection queries and dispatcher logic drift.

### REQ-002: Job dispatcher must gate each action on an explicit status set

- **Tier:** 5
- **Functional section:** Job dispatcher
- **Pattern:** whitelist
- **Specificity:** specific
- **Summary:** `process_job` must execute recover only for an explicit status set aligned with selection (`queued`, `retrying`, `restoring`); other statuses must no-op.
- **User story:** As an operator, I expect pending-approval recover Jobs not to call RestoreObject **so that** high-impact cost holds remain effective if selection queries widen.
- **Implementation note:** Today `elif job["action"] == "recover":` lacks a status conjunct unlike peers at `process_job`.
- **Conditions of satisfaction:**
  1. recover + pending_approval → return False / no `process_recover`.
  2. recover + queued|retrying|restoring (poll-eligible) → may run.
  3. upload/rename/free-space/cloud-* retain their existing status whitelists.
  4. cancelled always no-ops.
- **Alternative paths:** restoring deferral when age < restore_poll_interval
- **Use cases:** UC-03
- **References:** `app/storage.py:2196-2235`, `app/storage.py:2306-2388`

## Cloud lifecycle

Reversible archival hides the current key with a delete marker; purge permanently deletes pinned versions. Concurrent uploads make unversioned deletes dangerous.

### REQ-004: Reversible cloud hide must not silently hide an unexpected newer version without detection

- **Tier:** 5
- **Functional section:** Cloud lifecycle
- **Pattern:** parity
- **Specificity:** specific
- **Summary:** When executing cloud-archive (and analogous rename hide), the system must not hide a newer concurrent generation than the Job scheduled without abort or explicit audit of the actual marker target.
- **User story:** As an owner archiving a file, I expect the Job to affect the generation I scheduled **so that** a concurrent upload is not silently hidden.
- **Implementation note:** `process_cloud_archive` currently `delete_object` without VersionId; schedule pins `archive_version_id` in `cloud_deletion.py`.
- **Conditions of satisfaction:**
  1. Scheduled `archive_version_id` is loaded before delete.
  2. If current key generation ≠ scheduled expectation, Job aborts or audits mismatch (desired); today's code lacks this — Phase 3 verifies.
  3. Successful marker records returned marker VersionId.
  4. Rename hide-old-key shares the same concurrent-writer hazard class.
- **Alternative paths:** cloud-purge versioned delete (REQ-013)
- **Use cases:** UC-05
- **References:** `app/storage.py:2078-2130`, `app/storage.py:1622-1630`, `app/services/cloud_deletion.py:330-434`

### REQ-013: Cloud purge deletes pin VersionId

- **Tier:** 3

- **Specificity:** specific
- **Summary:** Permanent cloud purge must delete specific object versions / markers by VersionId, never unversioned current-key deletes for purge semantics.
- **User story:** As an owner purging, I expect only listed noncurrent versions removed **so that** unrelated current objects survive.
- **Implementation note:** `process_cloud_purge` uses versioned delete APIs.
- **Conditions of satisfaction:**

  2. pending_delay before deadline returns without work.
- **Alternative paths:** queued vs pending_delay status
- **Use cases:** UC-05
- **References:** `app/storage.py:2136-2164`

## Authentication and sessions

Break-glass and CSRF compose with proxy and session-version revocation.

### REQ-006: Break-glass allows only loopback ∪ configured CIDRs and fails closed

- **Tier:** 3
- **Functional section:** Authentication and sessions
- **Specificity:** specific
- **Summary:** `is_break_glass_allowed` denies missing/unparseable IPs; always allows loopback; otherwise requires membership in BREAK_GLASS_ALLOWED_CIDRS.
- **User story:** As an administrator, I expect break-glass unreachable from the public internet by default **so that** the emergency password cannot be brute-forced remotely.
- **Implementation note:** `app/breakglass.py`; ADR 0004.
- **Conditions of satisfaction:**
  1. None / garbage IP → False.
  2. 127.0.0.1 and ::1 → True even with empty CIDRs.
  3. Public IP with empty CIDRs → False.
  4. IP inside configured CIDR → True; outside → False.
- **Alternative paths:** bad CIDR config → deny
- **Use cases:** UC-07
- **References:** `app/breakglass.py:30-48`, `docs/adr/0004-break-glass-network-gating.md`

### REQ-007: Client IP trusts X-Forwarded-For only from Trusted Proxies

- **Tier:** 3
- **Functional section:** Authentication and sessions
- **Specificity:** specific
- **Summary:** `resolve_client_ip` ignores XFF unless the socket peer is in TRUSTED_PROXIES; then selects the rightmost untrusted hop.
- **User story:** As a deployer, I expect clients cannot forge break-glass source IPs unless I mistakenly trust their network **so that** network gating remains meaningful.
- **Implementation note:** `app/proxy.py`; ADR 0005.
- **Conditions of satisfaction:**
  1. Untrusted peer → return peer regardless of XFF.
  2. Trusted peer + XFF → rightmost untrusted hop.
  3. All hops trusted → hops[0].
  4. Missing peer → None.
- **Alternative paths:** none
- **Use cases:** UC-07
- **References:** `app/proxy.py:28-48`, `docs/adr/0005-host-csrf-reauth-hardening.md`

### REQ-008: CSRF token lookup should honor session_version revocation parity

- **Tier:** 5
- **Functional section:** Authentication and sessions
- **Specificity:** specific
- **Summary:** Force-logout via user `session_version` bump should invalidate CSRF acceptance equivalently to `resolve_session` rejection.
- **User story:** As a security-conscious admin forcing logout, I expect revoked session cookies cannot satisfy CSRF checks **so that** defense-in-depth holds if a future endpoint trusts CSRF alone.
- **Implementation note:** `csrf_token_for` currently omits session_version join; `resolve_session` enforces it.
- **Conditions of satisfaction:**
  1. `resolve_session` returns None when versions diverge.
  2. Desired: `csrf_token_for` also returns None when versions diverge (Phase 3 verifies gap).
  3. Expired/revoked sessions already return None from both.
- **Alternative paths:** middleware CSRF vs `current_user` resolution
- **Use cases:** UC-07
- **References:** `app/sessions.py:70-137`, `app/main.py:289-300`

### REQ-015: Session vault selection requires membership

- **Tier:** 3
- **Functional section:** Authentication and sessions
- **Specificity:** specific
- **Summary:** A session `vault_id` must not authorize operations on a vault the user no longer belongs to.
- **User story:** As a former member, I expect stale vault selection cannot mutate that vault **so that** membership revocation is effective.

## Gap iteration requirements (Iteration 2)

### REQ-020: Cloud rediscovery must preserve Vault File identity across Path History

- **Statement:** Recording an Archive Version or Delete Marker discovered at a logical path must not mint a new Vault File when that path is historical Path History for an active Vault File, or when the `(object_key, provider_version_id)` already exists.
- **Rationale:** CONTEXT.md — Vault File identity survives confirmed renames.
- **Source:** code-derived / CONTEXT.md · **Tier:** 3
- **Conditions of Satisfaction:**
  1. `record_archive_version` looks up existing archive_versions by object_key+VersionId before creating a Vault File.
  2. Cloud path resolution consults historical `file_paths` for active Vault Files before insert.
  3. Post-rename `scan_cloud` of an old key does not increase `vault_files` count for that identity.
- **Related bugs:** BUG-008

### REQ-021: Path History mutations must write durable audit_events

- **Statement:** Confirmed file/folder renames and auto-renames that mutate Path History inside a DB transaction must pass `connection` to `audit_log` so `/api/audit-events` can return them.
- **Rationale:** `audit_log` API contract (`app/audit.py`) — persist when connection provided.
- **Source:** code-derived · **Tier:** 5
- **Conditions of Satisfaction:**
  1. `confirm_rename` / `confirm_folder_rename` pass `connection`.
  2. `apply_auto_renames` passes `connection`.
  3. After confirm rename, an `audit_events` row exists for the rename event.
- **Related bugs:** BUG-009

### REQ-022: Configured off-host metadata backup failures must fail closed

- **Statement:** When `VAULT_S3_BUCKET` is configured, inability to construct the S3 object store must raise a backup failure rather than succeeding as local-only with `s3_key=None`.

### REQ-023: OIDC must not switch an active Session to a foreign linked identity

- **Statement:** If an authenticated Session exists and the OIDC callback resolves a different user_id, the callback must reject (403) rather than mint a session for the other user.
- **Rationale:** ADR-0003 self-link; ADR-0005 step-up refreshes existing session.
- **Source:** docs-derived (ADR) · **Tier:** 3
- **Conditions of Satisfaction:**
  1. Same-user callback refreshes reauth / rotates session.
  2. Cross-user while logged in raises 403.
  3. Logged-out login may still create a session for the resolved user.
- **Related bugs:** BUG-011

### REQ-024: Recover must not overwrite an existing on-disk Local Copy blindly

- **Statement:** When recovering an Archive Version, if a regular file already exists at the destination path on disk, the worker must refuse (or conflict) rather than `Path.replace` overwriting it solely because the catalog `local_presence` is not `present`.
- **Rationale:** Local Copy is the observed filesystem representation (CONTEXT.md). Catalog lag after free-space or external recreate must not cause silent data loss.
- **Source:** domain-inferred · **Tier:** 5
- **Conditions of Satisfaction:**
  1. Catalog `missing` + on-disk file present → recover fails closed (no overwrite).
  2. Catalog `missing` + path absent → recover may create via atomic replace.
  3. Catalog `present` continues to reject recover.
- **Related bugs:** BUG-012

### REQ-025: Crypt recovery must address the Archive Version object_key, not only the current job path

### REQ-026: Changing User.active must invalidate existing Sessions via session_version

### REQ-029: Cloud-archive post-Delete-Marker observability must not fail the job
