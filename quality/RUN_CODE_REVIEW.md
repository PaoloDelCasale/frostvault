## Pass 1: Structural Review

Read the code and report anything that looks wrong. No requirements focus — structural correctness only.

### Guardrails

- Line numbers are mandatory
- Read function bodies, not just signatures
- If unsure: QUESTION, not BUG
- Grep before claiming missing
- Do NOT suggest style changes

### Minimum scrutiny areas

#### 1. Input validation and boundary handling

- Job payloads (`archive_version_id`, paths, VersionIds)
- CIDR / IP parsing (`breakglass.parse_cidrs`, `proxy.parse_networks`)
- Operating window HH:MM and weekday bounds
- Empty `provider_version_id` on recovery

#### 2. Resource lifecycle

- Free-space claim rename + `restore_claimed_local_copy` on all failure paths
- Temporary recover files / atomic replace
- `vault_rclone_config` context cleanup
- DB connection commit/rollback in SQLite adapter

#### 3. Concurrency and state management

- Concurrent upload vs `process_cloud_archive` / `process_rename` unversioned delete
- `cancelled_jobs` in-memory set vs DB status
- `operation_process_lock` usage
- Session force-logout vs CSRF middleware ordering

#### 4. Unit and encoding correctness

- SHA-256 fingerprint comparisons for free-space and recover
- rclone crypt path vs object_key encoding helpers

#### 5. Enumeration and whitelist completeness

Mechanical check for `process_job` — use `quality/mechanical/process_job_action_branches.txt` (List A). Spec List B desired recover statuses: `{queued, retrying, restoring}`. Diff and report FOUND/NOT IN CODE. Run `./quality/mechanical/verify.sh` and attach receipt.

Do **not** copy lists from REQUIREMENTS.md — extract from `app/storage.py`.

### Priority files

`app/storage.py`, `app/services/cloud_deletion.py`, `app/sessions.py`, `app/proxy.py`, `app/breakglass.py`, `app/services/metadata_backups.py`, `app/services/vault_roles.py`, `app/main.py` (authz endpoints), `app/catalog.py`
