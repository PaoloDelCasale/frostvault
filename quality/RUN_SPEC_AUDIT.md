Give this prompt identically to three independent AI tools.

**Context files to read:**
1. `quality/REQUIREMENTS.md`, `quality/CONTRACTS.md`, `quality/QUALITY.md`, `quality/EXPLORATION.md`
2. `README.md`, `CONTEXT.md`, `SECURITY.md`

4. `docs/metadata-backups.md`, `docs/aws-s3-bucket.md`, `docs/filesystem-permissions.md`

**Task:** Act as the Tester. Read the actual code in `app/` and compare it against the specifications listed above and REQ-001..REQ-019.

**Requirement confidence tiers:** Weight by `[Req: tier — source]` / Tier 3–5 in REQUIREMENTS.md. Inferred (Tier 5) divergences → NEEDS REVIEW unless code-path proof is definitive.

**Rules:**
- ONLY list defects. Do not summarize what matches.
- For EVERY defect, cite specific file and line number(s).
- Before claiming missing, grep the codebase.
- Before claiming exists, read the actual function body.
- Classify: MISSING / DIVERGENT / UNDOCUMENTED / PHANTOM
- For inferred requirements, add NEEDS REVIEW when appropriate

5. `csrf_token_for` vs `resolve_session` session_version parity
6. `resolve_client_ip` + `is_break_glass_allowed` composition under forged XFF

## Running the Audit

1. Identical prompt → three AI tools
2. Independent — no cross-contamination
3. Collect three reports under `quality/spec_audits/`

## Optional secondary emphasis lenses

- Auditor A: input validation / VersionId boundaries
- Auditor B: resource lifecycle / free-space claim
- Auditor C: concurrency / proxy composition

## Triage Process

- Merge by confidence; minority findings require re-investigation with executable probes in `quality/mechanical/verify.sh` or `quality/spec_audits/triage_probes.sh`
- Do not raise evidentiary bar above code-path analysis
- Code review vs spec audit conflicts → verification probe with line-cited assertions

## Fix execution rules

Small batches by subsystem (`storage` jobs, auth/proxy, metadata backups, docs compensation). Patches only under `quality/patches/`.
