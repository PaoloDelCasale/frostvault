# BUG-003: List-only backup verification promoted to verified success

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-07-23 · Project: FrostVault

## 1. Summary

When `createdb` fails, PostgreSQL verify returns `ok: True` for TOC listing, and the scheduler marks the run `verified`.

## 2. Spec reference

- Primary requirement: REQ-005
- REQ-005 / QUALITY Scenario 4: list-only must not equal full isolated-restore success.

## 3. The code

`metadata_backups.py:447-456` returns ok True + `pg_restore_list`; `storage.py:2578-2600` sets `status='verified'` on ok alone.

## 4. Observable consequence

Operators believe dumps were restore-proven when only `pg_restore --list` succeeded.

## 5. Depth judgment

Both producer success shaping and consumer ignore-mode must be fixed; either side alone leaves false confidence.
