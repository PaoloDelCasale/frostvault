# BUG-002: Reversible cloud hide skips concurrent VersionId detection

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-07-23 · Project: FrostVault

## 1. Summary

Cloud-archive (and rename hide) create delete markers on the current key without verifying the live VersionId matches the scheduled Archive Version.

## 2. Spec reference

- Requirement: REQ-004
- Behavioral contract quote: "abort or audit when current ≠ scheduled generation"
- REQ-004: if current key generation ≠ scheduled expectation, abort or audit. Schedule pins `archive_version_id` in `cloud_deletion.py`.

## 3. The code

`process_cloud_archive` loads `provider_version_id` then calls `delete_object(Bucket, Key)` only (`app/storage.py:2099-2102`). Rename hide at `1622-1625` shares the pattern.

## 4. Observable consequence

A concurrent upload between schedule and execute can be silently hidden by the delete marker while the Job completes.

## 5. Depth judgment

Unversioned delete is required to create an S3 delete marker; the missing piece is Head/compare before delete, not VersionId on the delete call itself.
