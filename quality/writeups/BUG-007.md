# BUG-007: Operating windows compare HH:MM as lexicographic strings

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-07-23 · Project: FrostVault · Source: Spec Audit

## 1. Summary

`_normalize_windows` validates hour/minute as ints then compares raw strings, so HTTP-legal non-padded times (`OperatingWindowModel` allows length 4–5) can bypass the overnight/`start > end` guard and wrongly reject valid windows.

## 2. Spec reference

- Primary requirement: REQ-012
- CoS: `start > end` → ValueError; valid `start < end` accepted.

## 3. The code

`app/services/operation_policies.py:90-97` — int-parse for shape, then `if start >= end:` on strings. Runtime matching uses `_parse_hhmm` → `time` in `job_scheduler.py:107-109`.

## 4. Observable consequence

`start="10:00", end="9:30"` is accepted (inverted); `start="9:30", end="10:00"` is rejected. Padded times behave correctly, masking the bug in padded-only UIs.

## 5. Depth judgment

Minority finding (Auditor 1); Auditor 3 marked REQ-012 clean under padded examples. Probe confirms HTTP-reachable defect via `min_length=4`.

## 6. The fix

```diff
diff --git a/app/services/operation_policies.py b/app/services/operation_policies.py
--- a/app/services/operation_policies.py
+++ b/app/services/operation_policies.py
@@
-        if start >= end:
+        if (hour_start, minute_start) >= (hour_end, minute_end):
             raise ValueError("operating window start must be before end")
```

(Keep parsed `(hour, minute)` from both stamps instead of discarding them.)
