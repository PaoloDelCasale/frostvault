# BUG-019: Temp-database metadata verify reports success without proven schema

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.10 — Andrew Stellman
> Date: 2026-07-24 · Project: FrostVault · Source: Adversarial iteration (promoted from DC-011)

## 1. Summary

When PostgreSQL isolated verify successfully creates a scratch database but
`pg_restore` / table COUNT fails to prove `users`/`vaults`/`alembic_version`,
`_verify_postgres_dump_isolated` still returns `ok: True` with
`verification_mode: "temp_database"` and null counts. The scheduler then marks
the run `verified`.

## 2. Spec reference

- Requirement: REQ-031
- Docs: `docs/metadata-backups.md` — verification restores into an isolated
  temporary database
- Promoted from: DC-011 (distinct from rejected former BUG-003 list-only path)

## 3. The code

- Location: `app/services/metadata_backups.py:458-500`
- Divergence: accepts `pg_restore` rc ∈ {0,1}, leaves counts None when `psql`
  fails, returns `"ok": True` under `temp_database`.

## 4. Observable consequence

Operators believe a dump was restore-proven when the isolated DB never yielded
schema counts — false DR confidence on the full verification path.

## 5. Depth judgment

Producer must fail closed when temp_database mode cannot prove tables. Distinct
from intentional `pg_restore_list` fallback (former BUG-003, remains REJECTED).
