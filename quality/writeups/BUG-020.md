# BUG-020: Last-admin deactivation check races the UPDATE

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.10 — Andrew Stellman
> Date: 2026-07-24 · Project: FrostVault · Source: Adversarial iteration (promoted from DC-006)

## 1. Summary

`PATCH /api/admin/users/{id}` enforces “At least one administrator must remain
active” in a separate DB transaction from the UPDATE that clears `active`, with
no last-admin predicate on the UPDATE. Two concurrent deactivations can both
observe `COUNT=2` and both commit → zero active admins.

## 2. Spec reference

- Requirement: REQ-032
- Invariant stated in-handler: “At least one administrator must remain active”
- Promoted from: DC-006

## 3. The code

- Location: `app/main.py:2670-2700`
- Divergence: check-then-act across two `with db()` blocks; UPDATE is
  unconditional on last-admin count.

## 4. Observable consequence

All administrators can be deactivated, locking out admin recovery paths that
require an active admin session.

## 5. Depth judgment

Must use a single locked transaction and/or conditional UPDATE.
