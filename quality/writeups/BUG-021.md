# BUG-021: OIDC self-link creates invites without recent reauthentication

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.10 — Andrew Stellman
> Date: 2026-07-24 · Project: FrostVault · Source: Adversarial iteration (promoted from DC-013)

## 1. Summary

`GET /auth/oidc/link` creates a single-use invite and begins OIDC login using
only `current_user`, without `require_recent_reauth`. Admin invite creation
requires recent reauth. ADR-0005 lists invite creation as a sensitive action;
ADR-0003 defines self-link as invite issuance turned inward.

## 2. Spec reference

- Requirement: REQ-033
- ADR-0005: invite creation requires `reauth_at` within window
- ADR-0003: self-link issues an invite for the acting user
- Promoted from: DC-013 (DC-007 CSRF chain remains demoted)

## 3. The code

- Location: `app/main.py:1079-1096` vs admin invite `2643-2648`
- Adjacent: callback `mark_reauthenticated` without requiring `prompt=login` on
  self-link (`1131-1135` vs `984-988`)

## 4. Observable consequence

A stolen stale session can mint a self-invite and, via IdP SSO, bind an identity
and refresh the reauth window without a deliberate step-up.

## 5. Depth judgment

Gate `oidc_link` with `require_recent_reauth` and use `prompt=login` on
`begin_login` so callback refresh reflects a fresh provider login.
