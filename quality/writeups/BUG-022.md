# BUG-022: Invite redeem UPDATE is not single-use under concurrency

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.10 — Andrew Stellman
> Date: 2026-07-24 · Project: FrostVault · Source: Adversarial iteration (promoted from DC-002)

## 1. Summary

`redeem_invite` reads an invite, binds an identity, then `UPDATE`s by id only
without `WHERE redeemed_at IS NULL`. Concurrent redeemers can both observe an
unredeemed invite and both succeed; the second UPDATE clobbers redeemer fields.
Violates ADR-0003 single-use invites.

## 2. Spec reference

- Requirement: REQ-034
- ADR-0003: “single-use, expiring Invite”
- Promoted from: DC-002

## 3. The code

- Location: `app/invites.py:84-107`
- Schema: UNIQUE `(issuer, subject)` only — no single-redeem constraint on invite

## 4. Observable consequence

One invite can bind multiple subjects under concurrent PostgreSQL transactions
(SQLite serializes writers, masking the race locally).

## 5. Depth judgment

Conditional UPDATE + rowcount check (and ideally UNIQUE / transactional lock).

## 6. The fix

Proposed change from `quality/patches/BUG-022-fix.patch`:

```diff
diff --git a/app/invites.py b/app/invites.py
index 1703cdf..1f037f4 100644
--- a/app/invites.py
+++ b/app/invites.py
@@ -96,14 +96,30 @@ def redeem_invite(
     _bind_identity(
         connection, user_id=invite["target_user_id"], issuer=issuer, subject=subject
     )
-    connection.execute(
+    updated = connection.execute(
         """
         UPDATE invites
         SET redeemed_at=%s, redeemed_issuer=%s, redeemed_subject=%s
-        WHERE id=%s
+        WHERE id=%s AND redeemed_at IS NULL
         """,
         (_now().isoformat(), issuer, subject, invite_id),
     )
+    # Concurrent redeemers: second UPDATE matches 0 rows (ADR-0003 single-use).
+    rowcount = getattr(updated, "rowcount", None)
+    if rowcount == 0:
+        raise InviteError("already_redeemed")
+    if rowcount is None:
+        # Drivers that omit rowcount: re-read and confirm our redeem stuck.
+        row = connection.execute(
+            "SELECT redeemed_issuer, redeemed_subject FROM invites WHERE id=%s",
+            (invite_id,),
+        ).fetchone()
+        if (
+            not row
+            or row["redeemed_issuer"] != issuer
+            or row["redeemed_subject"] != subject
+        ):
+            raise InviteError("already_redeemed")
     return int(invite["target_user_id"])
```
